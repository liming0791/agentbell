## 结论

M1.5 的实现范围已经进入 Go 正式数据面：

- `qoder-work` 与 `trae` 均实现
  `detect -> plan -> install -> verify -> diagnose -> uninstall`；
- 交互 `agentbell setup` 能检测并安装两个 Adapter；
- `agentbell doctor` 输出两个 Adapter 的静态状态和 runtime proof 状态；
- `agentbell adapter uninstall all` 与顶层 `agentbell uninstall` 将两个 Adapter 纳入
  统一预检和精确卸载；
- 通知事件 Schema、来源显示名、runtime proof 白名单和机器可读 catalog 已同步。

两个 Adapter 仍为 Pilot。自动测试证明配置合并、事件语义和卸载边界，不能替代

以及 Windows 实机仍待补齐。

## 官方协议核对

### QoderWork

- 全局配置：国际版 `~/.qoderwork/settings.json`；QoderWork CN 使用独立
  `~/.qoderworkcn/settings.json`。Adapter 检测到 CN 数据根或 macOS CN App 时优先
  写入 CN profile，避免“静态 verify 通过但产品运行时未加载”的假阳性。
- Hook handler 使用单个 shell `command`，不是 Qoder 的 exec-form `command + args`。
- 当前安装事件：`Stop`、`PostToolUseFailure`、`PermissionRequest`。
- 官方明确不支持 Hook 热更新；安装或卸载后必须完全退出并重新启动 QoderWork。

### TRAE IDE

- 全局配置：国际版 macOS/Windows 使用 `~/.trae/hooks.json`；TRAE CN 使用独立
  `~/.trae-cn/hooks.json`，顶层格式版本为 `1`。Adapter 检测到 CN 数据根或
  macOS CN App 时优先写入 CN profile。
- macOS 使用 Bash、Windows 使用 PowerShell 执行 shell command。
- `Notification` 为异步、非阻塞事件：
  - `idle_prompt` 表示 Agent 已完成任务，映射为 `task.completed`；
  - `permission_prompt` 表示工具调用正在等待用户确认，映射为
    `approval.required`。
- AgentBell 只安装一个 matcher 为 `idle_prompt|permission_prompt` 的
  `Notification` Hook，不同时安装 `Stop`，避免同一任务产生两条完成通知。
- 用户必须在 TRAE 的 **设置 > Hooks > 全局** 中打开“已配置的 Hooks”，并把
  “Hooks 命令运行方式”设为“本地自动运行”。“沙箱运行”虽然会执行命令，但 AgentBell
  无法写入用户级队列和 runtime proof，且因 fail-open 表现为退出码 `0`，不能算通过。
  静态 `verify` 不能替代这一步，`diagnose` 只接受配置变更后的
  `task.completed` runtime proof。

官方证据链接见 [兼容矩阵](./compatibility.md#公开证据)。

## 2026-07-26 macOS 实机结果

测试环境：macOS 26.4（25E246）、Apple Silicon arm64。

- QoderWork CN 0.9.12：
  - 实际全局配置根为 `~/.qoderworkcn`，不是国际版 `~/.qoderwork`；
  - `PermissionRequest` 与 `Stop` 均由真实产品进程执行，热路径耗时约
    `25–82ms`；
  - 产品在等待 Hook 进程退出时不一定先关闭 stdin。Core 改为读取单个 JSON 值而不等待
    EOF 后，消除了固定约 `5s` 的 Hook 超时；
  - 最终 `diagnose` 返回 `runtimeVerified=true`，真实 `task.completed` 队列记录由
    LaunchAgent 发送后归档为 `succeeded`。
- TRAE CN 3.3.79：
  - 实际全局配置根为 `~/.trae-cn`；
  - 全局 Hook 开关关闭时，日志只显示配置解析成功而不会执行命令；
  - 开关打开但选择“沙箱运行”时，命令会执行并以 `0` 退出，但 AgentBell 用户级状态
    写入被沙箱隔离，`diagnose` 仍为未验证；
  - 切换为“本地自动运行”后，正式的异步
    `Notification.idle_prompt` Hook 约 `86ms` 完成，`diagnose` 返回
    `runtimeVerified=true`，真实 `task.completed` 队列记录归档为 `succeeded`；
  - 临时 `Stop` 只用于定位执行权限，最终配置已恢复为单个异步
    `Notification` Hook，没有保留双完成链路。
- macOS LaunchAgent：
  - 前台 `agentbell test` 成功而后台最初报 Keychain access blocked；
  - 根因是 LaunchAgent 未显式设置 `HOME`。服务定义补齐安装用户的 `HOME` 并重装后，
    QoderWork 与 TRAE 的真实事件均发送成功，错误日志没有新增 Keychain 失败。
